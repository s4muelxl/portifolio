Contexto e problema

Treino, refeições, finanças e rotina convivem no mesmo produto. O desafio é manter módulos diferentes coerentes sem transformar a experiência em vários aplicativos desconectados.

Minha responsabilidade

Estruturei a interface e os fluxos do produto, implementei regras de negócio e integrei autenticação, dados e operações do Supabase com a camada de estado da aplicação.

Decisão de implementação

  • Expo Router e React Native Web para a experiência mobile/web
  • Zustand para estado local e TanStack Query para consultas e sincronização remota
  • Supabase Auth, PostgreSQL, RLS e Edge Functions nas fronteiras de dados e servidor

Alternativas e limitações

Separar estado local de dados remotos reduz acoplamento, mas exige invalidação de cache e contratos claros quando uma ação afeta mais de um módulo. A experiência web também permanece sujeita às capacidades do navegador.

Entrega e validação

  • Scripts de typecheck, lint, testes Jest e testes das Edge Functions no repositório
  • Quality contracts e auditoria de segurança antes do build web
  • 13 telas reais documentam os principais fluxos do produto
